# 问题陈述

主模型曾使用扁平配置字段，备用模型使用不同的配置对象和构造路径。主模型独享生成参数，备用模型在降级后可能丢失这些参数；`provider` 同时承担供应商标识和客户端路由，语义不清晰。环境变量同时存在旧命名、公共 OpenAI 别名和备用链专用命名，示例文件也可能因启用不完整的备用模型而无法启动。

开发者无法仅查看一个配置对象就理解每个模型将如何被调用，也无法区分不可变的启动设置与会变化的降级、预算和运行时模型选择状态。

# 方案

每个可调用模型均使用同一种完整、不可变的 `ModelConfig`。启动时，命令行主模型覆盖、进程环境变量和当前目录 `.env` 被解析为不可变的 `Config` 快照；CLI 通过 `ModelChain.from_config()` 使用同一工厂创建主模型与备用模型。

运行时的当前级别、熔断、预算和显式模型名覆盖保留在 `ModelChain` 与 `BudgetState` 中，不回写启动配置。`backend` 选择受支持的客户端实现，`provider` 仅保留为可扩展的供应商标识。启动信息框仅展示 ZorinHelper、主模型和各备用模型的名称及 Base URL。

# 用户故事

1. 作为开发者，我希望主模型和每个备用模型使用相同的配置类型，以便直接比较其连接与生成行为。
2. 作为开发者，我希望每个已解析模型配置都包含完整请求参数，以便备用模型不会悄然使用不同的生成设置。
3. 作为运维者，我希望主模型和备用模型使用唯一、对称的环境变量格式，以便配置可预测。
4. 作为运维者，我希望每个模型级别声明自己的 API Key，以便凭据明确且不存在隐式继承。
5. 作为运维者，我希望进程环境变量覆盖当前目录 `.env`，以便部署配置具有明确优先级。
6. 作为运维者，我希望 CLI 只在冻结启动配置前覆盖主模型字段，以便命令行使用保持简单。
7. 作为开发者，我希望 `backend` 选择客户端实现，而 `provider` 保持可扩展的供应商标识，以便新增供应商名称不会改变路由语义。
8. 作为运维者，我希望不完整、跳号、未知或过时的配置在启动时带变量名失败，以便在发起请求前定位错误。
9. 作为用户，我希望 `/model` 只改变运行时主模型名并重置熔断，以便不修改启动配置或备用模型凭据。
10. 作为用户，我希望恢复会话时仅恢复显式模型名覆盖，而不恢复过期的备用级别、熔断或预算状态，以便每个进程使用当前配置和健康状态启动。
11. 作为开发者，我希望 `Config.summary()` 和 `ModelChain.status()` 可提供脱敏诊断信息，同时 CLI 启动信息框只显示模型名称和 Base URL，以便兼顾排障与可读性。
12. 作为开发者，我希望生产启动路径只有一个模型链工厂，以便主模型和备用模型不会经由不同的构造路径创建。
13. 作为运维者，我希望示例环境文件列出全部受支持字段，并默认不启用备用模型块，以便复制模板后仍然有效。
14. 作为维护者，我希望解析、构造、校验、脱敏和运行时边界均有自动化测试，以便配置契约保持稳定。

# 实现决策

- `ModelConfig` 是不可变配置单元，包含模型标识、显式 API Key、`backend`、`provider`、Base URL、`temperature` 和 `max_tokens`。
- `Config` 是不可变启动快照，包含一个主模型、按序的不可变备用模型元组、上下文上限和硬预算上限。
- 规范模型变量为 `CORECODER_PRIMARY_<FIELD>` 与 `CORECODER_FALLBACK_<N>_<FIELD>`；每一级的 `MODEL`、`API_KEY` 必填，其他模型字段使用固定默认值。备用索引从 1 开始且必须连续。
- 仅支持 `openai_compatible` 与 `litellm` 两种 `backend`。`provider` 必须为非空字符串，但不参与客户端类型选择。
- CLI 的 `--model`、`--base-url`、`--api-key` 仅作为主模型覆盖，在构造 `Config` 前参与解析。优先级依次为 CLI、进程环境变量、当前目录 `.env` 和默认值。
- 旧主模型变量与 OpenAI 别名不再兼容；发现时抛出包含迁移目标的配置错误。只加载当前目录 `.env`；若该文件存在但缺少 `python-dotenv`，启动失败。
- 在创建客户端前校验变量名、备用索引、必填值、`backend` 和数值范围。温度必须是有限非负数，输出与上下文 token 上限必须为正整数，预算必须是有限非负数。
- CLI 的生产启动路径通过 `ModelChain.from_config()` 构造模型链；其共享工厂把同一套已解析生成参数传给主模型和每个备用模型。直接注入 LLM 对象的构造方式仅保留给库调用和测试。
- `BudgetState` 位于独立的 `budget.py`，只保存进程级可变预算上限；`ModelChain` 负责在请求前进行跨模型预算准入。`LLM.has_known_cost` 公开当前模型是否可估算成本，模型链不读取 `llm.py` 的私有定价表。
- `/model` 只修改主模型客户端的运行时模型名、重置熔断并保留连接信息和备用链；不支持通过该命令切换 `backend`、`provider`、API Key 或 Base URL。
- 会话只保存消息和显式运行时模型名覆盖，不保存备用级别、熔断状态或累计预算。
- `Config.summary()` 与 `ModelChain.status()` 可以显示脱敏诊断信息，但不得显示 API Key 或 URL 查询参数。ZorinHelper 启动信息框仅显示主模型和各备用模型的名称及 Base URL。

# 测试决策

- 通过公开的配置解析与模型链创建入口测试，不直接依赖私有解析函数。
- 验证等价的环境变量和程序化输入会产生相同的不可变配置快照。
- 验证主模型与备用模型客户端都收到各自已解析的完整生成参数。
- 覆盖有效多后端链、必填字段缺失、未知字段、备用索引跳号、无效 `backend`、无效数值、旧变量和 dotenv 加载失败。
- 覆盖 CLI 优先级、仅运行时的 `/model` 更改、会话恢复边界、脱敏摘要、备用切换状态与精简启动模型信息。
- 复用现有配置、LiteLLM 与备用链测试中的假 LLM 接口；不发起真实供应商请求。

# 范围外

- 新增 OpenAI 兼容接口和 LiteLLM 以外的客户端后端。
- 跨进程持久化预算、熔断状态或已激活备用级别。
- 通过 `/model` 运行时切换供应商、后端、凭据或 Base URL。
- 支持旧主模型环境变量名称。
- 使用命令行语法直接构造备用模型链。
