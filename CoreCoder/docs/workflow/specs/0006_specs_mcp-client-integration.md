# MCP 客户端工具接入

## 问题陈述

CoreCoder 目前只能使用内置工具。接入数据库、第三方接口或其他外部能力时，维护者必须为每项能力单独实现新的 `Tool`，无法直接利用 MCP 生态中已有的 Server。

直接把 MCP SDK 嵌入现有 Agent 循环会引入异步生命周期、外部进程、工具名称冲突、不可信 Schema 与结果、权限授权、输出体积和异常清理等问题。项目当前还会在 Agent 构造时固定工具 Schema、名称索引和系统提示，因此运行期间动态修改工具集合会破坏这些状态的一致性。

MCP Server 配置还具有执行权限。若自动读取项目目录或项目 `.env` 中的配置，打开陌生工作区就可能启动其中声明的任意命令。MCP 接入必须在不削弱用户授权边界、受限 Agent 能力和 Agent 运行状态隔离的前提下完成。

## 解决方案

CoreCoder 第一阶段仅作为 MCP Client，通过官方 Python SDK v2 连接 stdio Server，并只消费 Tools。用户在固定的用户级配置文件中一次性声明 `mcpServers`；CoreCoder 后续启动、新对话和恢复会话时自动使用该配置。CLI 可以临时覆盖配置或禁用 MCP，项目目录和项目 `.env` 不参与 MCP Server 启动授权。

独立的 `McpRuntime` 负责 MCP 配置解析、Server 连接、后台事件循环、多 Server 会话、工具发现、调用转发、通知接收和关闭清理。每个远程工具由 `McpTool` adapter 适配为现有同步 `Tool` interface，Agent 不直接依赖 MCP SDK，也不改为异步实现。

Agent 的 `tools=` 保持完整替换语义，新增 `extra_tools=` 追加外部能力。默认 CLI Agent 使用内置工具加 MCP 工具；受限 Agent 仍可通过 `tools=` 精确声明完整能力集合。子 Agent 重新创建自己的内置工具和 Agent 运行状态，并继承父 Agent 的附加工具，包括 MCP 工具，但排除 `agent`。

工具在启动阶段完成发现、验证、命名和注册，形成 MCP 工具快照。运行期间收到工具列表变化通知时，CoreCoder 在下一次显示交互提示符前要求用户重启，不动态重建 Agent。所有 MCP 工具默认不可并发，不采信 Server annotations。

## 实现决策

- CoreCoder 仅实现 MCP Client，不实现 MCP Server。
- 第一阶段仅支持 Tools 和 stdio transport，不支持其他 MCP 能力或 transport。
- 官方 Python SDK 作为 `corecoder[mcp]` 可选依赖引入，版本范围为 `mcp>=2,<3`；未启用 MCP 时不得导入或要求该依赖。
- 默认用户级 MCP Server 配置位于 `~/.corecoder/mcp.json`。CLI 的 `--mcp-config` 优先于默认文件，`--no-mcp` 禁用本次启动的 MCP；两者同时出现时配置无效。
- 项目目录和项目 `.env` 不作为 MCP 配置来源。会话文件不保存 MCP 配置路径、Server 定义或凭据。
- `corecoder --help` 和 REPL `/help` 均展示 `--mcp-config` 与 `--no-mcp`，并明确它们是启动参数。
- 配置根对象只接受 `mcpServers`。每个 Server 只接受必填字符串 `command`、可选字符串数组 `args` 和可选字符串映射 `env`；未知字段、错误类型、空命令和缺失环境变量引用均在启动时失败。
- `env` 值允许普通字符串和 `${VARIABLE}` 引用。Server 环境以当前进程环境为基础，再由解析后的 `env` 覆盖；敏感值不得出现在启动摘要或会话文件中。
- stdio Server 使用可执行文件和参数直接启动，不通过 Shell，并继承 CoreCoder 启动时的当前工作目录。
- `McpRuntime` 是所有 MCP 会话、后台事件循环、Server 子进程、通知和关闭行为的唯一生命周期所有者。它使用一个后台事件循环和一个 `ClientSessionGroup` 管理全部 Server。
- CLI 在 Agent 构造前建立 `McpRuntime`、连接 Server、获取工具并形成 MCP 工具快照，在 CLI 退出的统一清理路径中关闭 Runtime。
- Server 连接超时为 30 秒，工具调用超时为 120 秒。第一阶段不提供 per-Server 超时配置。
- MCP 工具调用不自动重试；Server 进程退出或连接失效后不自动重连，相关工具返回明确的不可用错误，用户通过重启 CoreCoder 恢复。
- 正常退出和中断均触发关闭。Runtime 最多等待 5 秒完成优雅关闭，随后终止残留 stdio 子进程。
- 无效配置使启动失败。单个 Server 连接、初始化、工具 Schema 或名称验证失败时，该 Server 被标记失败，其他 Server 继续；全部 Server 失败或最终没有任何可用 MCP 工具时启动失败。
- 启动摘要只显示 Server 配置键、连接结果、错误摘要和工具数量，不显示 `command`、`args`、`env` 或凭据。
- MCP 工具的模型可见名称为 `mcp__<server配置键>__<工具原名>`。名称只允许 ASCII 字母、数字、下划线和连字符，最长 64 字符；规范化后发生冲突或超过限制时，对应 Server 失败，不截断或静默覆盖。
- `McpTool` adapter 直接复用 Server 提供的 `inputSchema` 作为现有工具参数 Schema，不增加本地 JSON Schema 校验；Server 的工具执行错误被保留为可供模型修正的工具结果，协议和连接错误被转换为明确错误。
- 只接受文本内容和结构化 JSON。其他内容类型返回不支持错误，不进行 Base64 编码或多模态消息改造。
- MCP 工具结果超过 15,000 字符时，采用与现有 Shell 工具一致的头尾保留策略并标明原始长度。
- 调用提示显示工具名和经过限长的参数摘要。字段名包含 `key`、`token`、`secret`、`password`、`auth` 或 `credential` 时，相关值在任意嵌套层级均被遮蔽。
- `Agent.tools` 参数保持完整替换语义；新增 `extra_tools` 参数，在默认工具或显式 `tools` 基础上追加工具。最终工具集合在构造阶段固定且名称必须唯一。
- 工具 Schema、名称索引和系统提示从同一个已验证工具集合一次性生成。重复名称必须抛出明确错误，禁止字典静默覆盖。
- 子 Agent 继承父 Agent 的有效能力但不直接复制所有工具实例：它重新创建自己的内置工具和 Agent 运行状态，继承父 Agent 的附加工具，包括共享同一 `McpRuntime` 的 MCP 工具，并排除 `agent`。
- 所有 MCP 工具保持 `concurrency_safe = False`，不根据 `readOnlyHint`、`destructiveHint`、`idempotentHint` 等 Server annotations 放宽并发策略。
- MCP 工具列表只在启动时获取。收到工具列表变化通知后，把提示加入队列，并在下一次显示 REPL 提示符前通知用户重启；不动态修改正在运行的 Agent。
- 启动时估算系统提示和全部工具 Schema 的上下文占用。估算值超过上下文上限时启动失败，超过上限的 25% 时显示警告。
- 保存与恢复会话仍只处理既有会话数据。若恢复的历史包含 MCP 工具调用，而本次 MCP 未启用，应提示当前不会提供 MCP 工具，但不得从会话内容推断并启动 Server。
- MCP Server 自身调用第三方服务产生的费用不计入 CoreCoder 的 LLM 硬预算。工具调用事实可以显示和测试，但不估算外部费用。

## 测试决策

- 测试以公开 interface 的可观察行为为准，不断言后台事件循环、SDK 内部对象或私有集合的具体组织方式。
- Agent 工具组合测试覆盖默认工具、完整替换、附加工具、空工具集合、重复名称和 Schema/名称索引一致性。
- 父子 Agent 测试覆盖 MCP 能力继承、`agent` 排除、内置有状态工具重新创建、Agent 运行状态隔离和共享 MCP 生命周期。
- MCP 配置测试覆盖默认用户级路径、CLI 覆盖、禁用选项、字段类型、未知字段、环境变量展开、缺失引用以及项目 `.env` 不参与授权。
- CLI 测试覆盖两种帮助界面、启动摘要脱敏、部分失败、全部失败、缺少可选依赖、恢复会话提示和工具变化提示队列。
- `McpRuntime` 通过可替换的假 SDK adapter 测试多 Server 连接、工具发现、调用转发、超时、错误、通知和关闭行为。
- `McpTool` 测试覆盖名称生成、输入 Schema 复用、文本与结构化结果、执行错误、不支持内容类型、参数摘要脱敏和输出截断。
- 并发测试通过 Agent interface 验证 MCP 工具始终进入串行段，Server annotations 不改变调度。
- 增加一个不访问互联网的最小本地 stdio Server 集成测试，验证真实进程启动、初始化、工具列表、工具调用、列表变化通知和关闭清理。
- 连接失败测试只使用本地失败进程或假 adapter，不依赖真实第三方 Server。
- 复用现有假模块注入、直接构造 Agent、CLI 输出捕获和工具调度测试模式，不引入新的测试框架。

## 范围外事项

- 将 CoreCoder 暴露为 MCP Server。
- Resources、Prompts、Roots、Sampling、Elicitation、Tasks 或其他非 Tools 能力。
- Streamable HTTP、旧 SSE 和自定义 transport。
- 运行期间动态刷新 Agent 工具集合。
- 自动重试、自动重连和逐次工具调用审批。
- 根据 Server annotations 或用户配置覆盖 MCP 工具并发属性。
- MCP 工具 allowlist、按需工具发现或工具搜索。
- 图片、音频、ResourceLink、EmbeddedResource 等多模态或资源结果。
- 在客户端重复执行完整 JSON Schema 参数校验。
- 从项目配置、项目 `.env` 或会话文件自动获得 MCP Server 启动权限。
- 估算或限制 MCP Server 调用外部服务产生的费用。
- 自动安装 MCP SDK 或其他依赖。
- 真实第三方 MCP Server 或互联网端到端测试。

## 补充说明

- 本功能复用并发调度的默认拒绝规则、共享模型预算与熔断状态，以及 Agent 私有工具运行状态等既有设计。
- MCP 工具共享的是外部连接生命周期，不改变父子 Agent 各自拥有独立内置工具运行状态的约束。
- 用户级 MCP Server 配置代表持久授权。临时覆盖和禁用选项用于特定工作区、诊断与安全场景。
- 原功能编号 `0003` 的 MCP 方案已废弃；本功能使用新的 `0006` 文档组。
